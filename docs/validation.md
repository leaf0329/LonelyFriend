## 自动回归

原有 12 项覆盖：

- 私聊与群聊名单分离、空名单拒绝、管理员不绕过名单及账号格式边界。
- 超过 80 轮的短对话不被机械裁掉。
- 总结服务失败时，保留最新请求和完整工具调用轮次，并缩减旧工作上下文。
- 长消息完整保存、去重、重启后回查尾部细节。
- 同一用户能读到自己的原文作为正向对照，另一位用户和群聊读不到。
- 60 天前已总结原文不被维护清理；已停止传播的事件不被原文适配器保存。

新增 4 项覆盖：

- 同义问题能发现正确原文；另一位用户和群聊即使知道来源引用也读不到私聊内容。移除工具后不会偷偷自动注入原文。
- 超过一万字符的消息完成超过单次批次上限的后台索引；重启后能语义找回末尾相机的存放位置。
- 本地模型缺失时明确返回语义检索不可用，已有关键词与原文查询仍可使用。
- 最终答复替换工具调用前的缓冲铺垫，避免同时发出“没印象”和已经查到的名字。

这些检查使用实际框架和记忆库，不调用社交平台账号。

## 原生消息链路

在隔离目录启动真实 AstrBot，加载 MemoryCompanion 和项目原文适配器，用本地 OneBot 客户端模拟 QQ 消息：

1. 输入一条 6549 字的虚构消息，核对数据库正文与输入一致。
2. 执行原生 `/new`，确认创建了新对话。
3. 通过真实 DeepSeek 与原生记忆工具，找回长消息末尾的花名“青柚回声”。
4. 清空短期上下文后，换用“抢我功劳”提问，找回原文中的名字“赵衡”。
5. 核对指定账号的固定称呼，以及不输出括号动作的角色要求。
6. 群成员不能用 `/new` 清除共享上下文；获准管理员执行后，仍能回忆群里的旧书交换地点和时间。
7. 群内追问不能带出私聊中的名字；其他成员不会被套用指定账号的固定称呼。
8. 输入未获准账号的消息，核对没有回复且没有存入时间线。

以上通过，精简结果见 [消息链路结果](evaluations/pipeline-semantic.json)。测试使用了真实模型与原生消息处理流程，但 OneBot 对端是本地模拟器，不能替代 QQ 客户端的真实登录和收发验收。所有隔离验收进程均在结束后关闭。

正式记忆库另完成 6 个既有窗口的本地索引回填，没有把旧记录重新绑定到其他账号或人格，也没有调用额外的远程 Embedding 服务。这个数字只表示当时存在并可识别的分区，不表示长期样本规模。

## 验收发现与修正

| 发现 | 处理与证据 |
| --- | --- |
| 原文元数据的 JSON 字符串没有被投影器识别，语义索引误截到 4000 字符 | 在版本固定的接口边界规范元数据；长消息末尾语义回归通过 |
| 原生索引处理完单批次就停下，等待下条消息才继续 | 后台有界推进；超过批次上限的长消息不需下一次聊天即可完成索引 |
| 语义发现工具缺少查询参数描述 | 修正已获准工具的描述，不增加已移除工具的权限；真实链路同义追问通过 |
| 模型说“我翻翻”却没有实际查找 | 提示要求当轮查找；对原生判定的历史追问，首答前自动补入获准候选 |
| 查找前后的回答被拼在一起，出现前面说没印象、后面答出名字 | 缓冲中间文字并使用本轮最终回答；实际消息链路与输出回归通过 |
| 测试中的身份提示优先级与实际运行不同 | 调整测试以与系统身份提示一致；群成员归属定向重测通过 |
| 隔离 OneBot 测试没有正确区分异步到达的回复，以及误把普通群成员当作可重置上下文的管理员 | 测试开启引用关联输入；分别验证普通成员和管理员权限，正式引用设置保持原值 |

依赖检查 `pip check` 通过。Embedding 模型按固定修订下载，实际聊天读取本地文件；模型缓存约 90.8 MiB，尚未计入进程内存和后续索引增长。

## 尚未覆盖的边界

- 真实 QQ、空间、B 站、小黑盒账号登录及发布可见性仍需逐个平台验收。
- 自然聊天中的模糊指代、长期情绪与人物关系，不由本次有限问题集全面证明。
- 已启用本地向量模型，但隐喻、多人长对话、指代模糊和大规模历史仍可能召回不足；没有进行百万条历史或高并发压力测试。
- 完整原文适配器目前覆盖获准 QQ 来信的文字，单条正文受底层 256 KiB 边界限制；媒体和角色回复不是同等范围的完整档案。
- 用户切换人格、第三方组件升级、跨系统迁移及全新电脑重建，需要相应的独立验证。
- 原文保留会增加磁盘与检索开销；被选中的资料仍通过 API 交给模型处理。
- 遗忘半衰期采用上游的分类近似，未经过个人心理模型拟合；本轮没有用数月真实交谈证明长期陪伴效果。
