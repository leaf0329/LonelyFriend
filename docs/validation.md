# 记忆与运行验证

验证日期：2026-10-25。所有记忆测试人物、经历和账号标识均为虚构资料，测试数据库与正式记忆库隔离。

## 对照方法

改进前配置取自 Git 标签 [`baseline-deployed-2026-10-24`](https://github.com/leaf0329/LonelyFriend/tree/baseline-deployed-2026-10-24)。改进配置使用 `config/memory-policy.json`。

两组均使用安装中的 MemoryCompanion 原生存储、阶段总结、检索、可见性与原文工具，以及真实的 `deepseek-flash`。同一份虚构聊天包含两名用户、退租押金的金额更正与分次归还、不同朋友还东西、情绪原因、方案后续和未提供的生日。每组执行自己的原生总结与维护，然后关闭并重新打开数据库，在没有上一轮短期对话的情况下回答相同的 8 个问题。

消息时间设置在 2026 年 9 月，覆盖默认 30 天保留策略。对照测试没有使用真实 QQ 账号，也没有让测试资料进入正式记忆。

## 自动回归

`python -m unittest discover -s tests -v` 共 12 项检查通过：

- 私聊与群聊名单分离、空名单拒绝、管理员不绕过名单及账号格式边界。
- 超过 80 轮的短对话不被机械裁掉。
- 总结服务失败时，保留最新请求和完整工具调用轮次，并缩减旧工作上下文。
- 长消息完整保存、去重、重启后回查尾部细节。
- 同一用户能读到自己的原文作为正向对照，另一位用户和群聊读不到。
- 60 天前已总结原文不被维护清理；已停止传播的事件不被原文适配器保存。

这些检查使用实际框架和记忆库，不调用社交平台账号。

## 原生消息链路

在隔离目录启动真实 AstrBot，加载 MemoryCompanion 和项目原文适配器，用本地 OneBot 客户端模拟 QQ 消息：

1. 输入一条 6549 字的虚构消息，核对数据库正文与输入一致。
2. 执行原生 `/new`，确认创建了新对话。
3. 通过真实 DeepSeek 与原生记忆工具，找回长消息末尾的花名。
4. 输入未获准账号的消息，核对没有回复且没有存入时间线。

此项通过，回答为“青柚回声”。测试使用了真实模型与原生消息处理流程，但 OneBot 对端是本地模拟器，不能替代 QQ 官方客户端的真实收发验收。

## 上下文整理

对一组 92 轮的小型虚构上下文执行实际模型摘要，将本地估算 token 从 2729 缩减到 956；最近请求保留，最早的盆栽名字仍可回答。记录见 [上下文结果](evaluations/context-compression.json)。

生产配置在约 656000 个估算 token 时开始整理，给 [模型上下文窗口](https://api-docs.deepseek.com/api/list-models/)和输出预留余量。该测试使用缩小的隔离预算触发相同压缩代码，没有发送百万 token 压力请求。

## 尚未覆盖的边界

- 真实 QQ、空间、B 站、小黑盒账号登录及发布可见性仍需逐个平台验收。
- 自然聊天中的模糊指代、长期情绪与人物关系，不由本次有限问题集全面证明。
- 未启用额外的向量模型；关键词不重合或线索模糊时仍可能召回不足。
- 完整原文适配器目前覆盖获准 QQ 来信的文字，单条正文受底层 256 KiB 边界限制；媒体和角色回复不是同等范围的完整档案。
- 用户切换人格、第三方组件升级、跨系统迁移及全新电脑重建，需要相应的独立验证。
- 原文保留会增加磁盘与检索开销；被选中的资料仍通过 API 交给模型处理。
